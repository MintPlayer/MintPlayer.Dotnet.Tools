# PRD: `[ImplementInterface]` — generate interface implementations

## Overview

A new attribute, `[ImplementInterface(params Type[] interfaces)]`, placed on a partial type, makes
`MintPlayer.SourceGenerators` add those interfaces to the type's base list and implement every
interface member that is still unimplemented, **when the body is obvious**:

- read/write properties (instance and static) become auto-properties `{ get; set; }` / `{ get; init; }`;
- on an **abstract** target, every other instance member (methods, get-only and set-only properties,
  events, indexers) becomes a `public abstract` declaration, and the concrete subclass supplies it;
- on a concrete target, every other member is a compile error unless the user implemented it by hand.

```cs
[ImplementInterface(typeof(ICustomerManagement), typeof(IWarehouseManagement))]
public partial class CarDealerContext { }

public interface ICustomerManagement
{
    IRavenQueryable<Customer> Customers { get; set; }
}

public interface IWarehouseManagement
{
    IRavenQueryable<Part> Parts { get; set; }
    IRavenQueryable<Supplier> Suppliers { get; set; }
    // ...
}
```

generates (in the single file `ImplementInterface.g.cs`):

```cs
// <auto-generated/>
#nullable enable
partial class CarDealerContext : global::ICustomerManagement, global::IWarehouseManagement
{
    public global::Raven.Client.Documents.Linq.IRavenQueryable<global::Customer> Customers { get; set; } = default!;
    public global::Raven.Client.Documents.Linq.IRavenQueryable<global::Part> Parts { get; set; } = default!;
    // ...
}
```

The user writes the members only they can write. The generator writes the boilerplate.

## Problem Statement

Context classes that group many queryable collections, such as RavenDB `IRavenQueryable<T>`,
EF-style sets, or settings aggregates, are split into role interfaces (`ICustomerManagement`,
`IWarehouseManagement`). Consumers then depend only on the slice they need. Today every property
has to be written out again on the implementing class, in the same shape, once per interface. This
causes three problems:

- It is pure duplication. Adding a property to an interface forces an edit to every implementor.
- The compiler error for a forgotten member (CS0535) shows up on the class, far from the interface
  change that caused it.
- The pattern stops people from splitting interfaces finely. More interfaces means more copying.

## Goals

1. One attribute that implements any number of interfaces with plain auto-properties.
2. Members the user writes by hand always win. The generator fills only the gaps.
3. Abstract base classes defer everything without an obvious body to their subclasses.
4. Clear errors, reported on the attribute or on the offending member, for members that need a body.
5. Tooling that closes the loop: code fixes for adoption, a "move to interface" action that works
   with INTF001, and clean-up of hand-written properties that have become redundant.
6. Follow the house conventions: a fixed file set, value-equatable models with no Roslyn types,
   rule ids in `AnalyzerReleases.Unshipped.md`, and coverage in the guard tests.

## Non-Goals

- Bodies for methods, events or indexers on concrete targets, including
  `throw new NotImplementedException()` stubs. A stub hides a gap until runtime, so it stays an error.
- **An opt-in for get-only and set-only properties on concrete targets (the former X4).** These
  properties are allowed on the interface, but the user implements them by hand. Otherwise the error
  is reported. *Decided at grill time:* the right shape (`{ get; }`, `private set`, `init`) depends on
  the class, and a generated choice would be a guess.
- `INotifyPropertyChanged`-backed setters. That collides with MVVM Toolkit and similar generators,
  and it is a different feature.
- Copying attributes from interface properties onto the generated properties. Many attributes are
  not valid there, and the intent is ambiguous.
- Open generic interfaces (`typeof(IRepo<>)`) and interfaces that mention the target's own type
  parameters. C# cannot express those in an attribute (CS0416).
- Making read/write properties `abstract` on abstract targets. They stay concrete auto-properties.

## Requirements

### R1 — Attributes

`MintPlayer.SourceGenerators.Attributes/ImplementInterfaceAttribute.cs`:

```cs
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Struct, AllowMultiple = true, Inherited = false)]
public sealed class ImplementInterfaceAttribute : Attribute
{
    public ImplementInterfaceAttribute(params Type[] interfaces) { }

    /// Implement this attribute's interfaces explicitly (T IA.P { get; set; }) instead of publicly.
    public bool Explicit { get; set; }

    /// Initialise non-nullable reference-type properties with `= default!`. Set to false to let CS8618 report them.
    public bool InitializeNonNullable { get; set; } = true;
}

[AttributeUsage(AttributeTargets.Class | AttributeTargets.Struct, AllowMultiple = true, Inherited = false)]
public sealed class ImplementInterfaceAttribute<TInterface> : Attribute
{
    public bool Explicit { get; set; }
    public bool InitializeNonNullable { get; set; } = true;
}
```

- `AllowMultiple = true`. The generator takes the union across all attribute instances (both forms)
  on all partial parts.
- **Named arguments apply per attribute instance.** For a mix, write two attributes:
  `[ImplementInterface(typeof(IA))]` and `[ImplementInterface(typeof(IB), Explicit = true)]`.
- This is the first attribute in the package with `params Type[]`. Discovery must read
  `ConstructorArguments[0].Values` and must also handle the single-argument and empty cases.
- The generic form reads `AttributeClass.TypeArguments`. It needs consumer LangVersion 11 or later.
  Below that, the compiler already reports the error, and the generator ignores the attribute.

### R2 — Which interfaces and members

1. Each interface named in the attributes is resolved, deduplicated by symbol, and its
   `AllInterfaces` is expanded. Each interface member is processed **once**, which makes diamonds
   safe.
2. Only the interfaces named in the attribute are added to the base list. Inherited ones come along
   implicitly. An interface the type already lists, in any partial part or through its base class,
   is not repeated, because that would be CS0528. Listing an interface in the base list **and** in the
   attribute is allowed and reports nothing.
3. For each abstract member, the generator asks
   `target.FindImplementationForInterfaceMember(member)`. If that returns a member, the generator
   **skips** it. This covers members written by hand, members inherited from a base class, and
   members implemented explicitly.
4. A member with the right name and the **wrong type** written by hand is not an implementation.
   The generator skips that name and reports IMPLINTF009 on the hand-written member (R5).
5. Members with a default implementation (DIM, static virtual with a body) are skipped.
6. Two members with the same name and the same type (nullability included) become **one** public
   member, which implicitly satisfies both interfaces.
7. **Collision fallback.** Two read/write properties with the same name and different types: the
   interface listed first (attribute order, then `typeof` order) gets the public property, and the
   others get explicit implementations. A collision the fallback cannot resolve is IMPLINTF005. That
   happens when the colliding member would have to be `abstract` (C# has no abstract explicit
   implementation).

### R3 — The emitted member shape

| Interface member | Concrete target | Abstract target |
|---|---|---|
| `T P { get; set; }` | `public T P { get; set; }` | same (stays concrete) |
| `T P { get; init; }` | `public T P { get; init; }` (mirrored: `set` cannot implement `init`, CS8854) | same |
| `static abstract T P { get; set; }` | `public static T P { get; set; }` | same |
| get-only / set-only / `ref` property | IMPLINTF004 | `public abstract T P { get; }` (accessors mirrored) |
| method, including generic | IMPLINTF003 | `public abstract R M<...>(...) where ...;` (type parameters, constraints, `ref`/`out`/`in`/`params`, and default values mirrored) |
| event | IMPLINTF003 | `public abstract event E? X;` |
| indexer | IMPLINTF003 | `public abstract T this[...] { get; set; }` (accessors mirrored) |
| any other static abstract member | IMPLINTF003 | IMPLINTF003 (C# has no static abstract members in classes) |

- With `Explicit = true` the generated members are `T IA.P { get; set; }`. On an abstract target, a
  member that would have to be both explicit and abstract is reported instead (IMPLINTF003/004).
- **Nullability.** The file starts with `#nullable enable`. This is required, because Roslyn treats
  generated source as nullable-disabled whatever `<Nullable>` the project sets. Types are written fully
  qualified (`global::`) with their annotations. Properties whose interface type is nullable-*oblivious*
  (from an assembly or project with nullable disabled) are emitted inside
  `#nullable disable annotations` / `#nullable enable annotations`, so the generated property never
  claims more than the interface does. (`restore` would return to the generated file's default, which is
  disabled, not to the `#nullable enable` at its top.)
- **Initializer.** If `InitializeNonNullable` is true (the default), a non-nullable reference-type
  property gets `= default!;`. Value types, nullable types, and oblivious types get no initializer.
  Instance properties on struct targets never get one: a struct with an instance initializer and no
  constructor is CS8983, and structs raise no CS8618 anyway (S1). Static struct properties do get one.
- Never emit `required`. It breaks every existing `new X()`.
- If the property type is less accessible than the target (CS0053), use an explicit implementation.
  S5 confirmed that this compiles.

### R4 — Targets

| Target | Behaviour |
|---|---|
| `class`, `sealed class`, `record`, `struct`, `record struct` | generate (concrete rules) |
| `abstract class`, `abstract record` | generate (abstract rules, R3) |
| nested in partial types | generate, through `GetPathSpec` / `OpenPathSpec(spec, includeTarget: true, baseList: ...)` |
| generic target `Foo<T>` | generate, using only closed interfaces that do not mention `T` |
| not partial, or a containing type not partial | IMPLINTF001 |
| `interface`, `static class`, file-local | IMPLINTF006 (file-local follows `PathSpec.UnsupportedReason`) |

### R5 — Diagnostics

The rules use the new prefix `IMPLINTF`, kept apart from the analyzer id `INTF001`. Category is
`MintPlayer.SourceGenerators`.

| Id | Severity | Reported on | When |
|---|---|---|---|
| IMPLINTF001 | Error | the type identifier | The target or a containing type is not `partial` |
| IMPLINTF002 | Error | the `typeof` / type argument | Not an interface (class, struct, enum, delegate), or an unbound generic `IRepo<>` |
| IMPLINTF003 | Error | the attribute | An unimplemented **method, event, indexer or static non-property member** on a concrete target; any static abstract non-property member; an abstract member that `Explicit` would need to make explicit |
| IMPLINTF004 | Error | the attribute | An unimplemented property that is not read/write (get-only, set-only, `ref` return, non-public accessor) on a concrete target |
| IMPLINTF005 | Error | the attribute | Same name, different types, and the R2.7 fallback cannot resolve it |
| IMPLINTF006 | Error | the type identifier | Unsupported target kind (interface, static class, file-local) |
| IMPLINTF007 | Warning | the duplicate argument | The same interface named twice across the `[ImplementInterface]` attributes (base-list duplicates are fine) |
| IMPLINTF008 | Info | the hand-written property | A hand-written property is **redundant**: the generator would produce it identically |
| IMPLINTF009 | Error | the hand-written member | A hand-written member has the interface member's name but a different type. Fix the type, or delete the member and let the generator implement it |

- The generator reports IMPLINTF001–007 and IMPLINTF009 through `Discovered.Fail` /
  `DiagnosticInfo.Create` (a rule id, a `LocationKey` and string args). Models never hold a
  `Location`. IMPLINTF008 comes from an analyzer (R7), because it is about hand-written code and
  carries a code fix.
- **Redundancy rule (IMPLINTF008, and the INTF001 action in R7).** Only a bare
  `public T P { get; set; }` / `{ get; init; }` that has no attributes, no initializer, no accessor
  modifiers, no `virtual` / `override` / `new`, and that matches the interface type exactly, counts.
  Anything else carries behaviour the generator does not copy.
- **Error UX (spike S4).** The working assumption is that when IMPLINTF003/004/005 fire, the
  supported members are still emitted and the base list is still written. The rest of the consumer's
  code then keeps compiling, and the build fails on our error rather than on a cascade. CS0535 /
  CS0738 appear beside ours, and that duplication is accepted (see IMPLINTF009 too).

### R6 — Pipeline

- `ImplementInterfaceSourceGenerator.cs`, `.Producer.cs` and `.Rules.cs` in `Generators/`.
- Two `ForAttribute` registrations, for the non-generic metadata name and the generic one
  (`` ImplementInterfaceAttribute`1 ``), both with the predicate `node is TypeDeclarationSyntax`.
- Model `ImplementInterfaceDeclaration` (`[GenerateEquality]`): the `PathSpec`, `IsAbstract`, the
  base-list entries as strings, and a member list. Each member records its kind, its name, its type
  display, its accessors, `IsStatic`, `IsExplicit` plus the explicit interface display,
  `NeedsInitializer`, `IsOblivious`, and for methods a pre-rendered signature (type parameters,
  parameters, constraints). It holds only strings, bools, enums and equatable arrays.
- `.Models().Collect().Join(settingsProvider).Select(... new ImplementInterfaceProducer(models, rootNamespace))`.
- One fixed hint name, `ImplementInterface.g.cs`. Attribute instances and partial parts are merged
  into one model per target type before the producer runs. Spike S3 checks where that merge happens.

### R7 — Analyzers and code fixes

| Fix | On | Action |
|---|---|---|
| **Make partial** | IMPLINTF001 | add `partial` to the target and every containing type that lacks it |
| **Implement with [ImplementInterface]** | CS0535 | add `[ImplementInterface(typeof(I))]`, or append `typeof(I)` to an existing non-explicit attribute. **Keep** `I` in the base list (R2.2) |
| **Move to interface** (new INTF001 action) | INTF001 | when the member passes the redundancy rule and the chosen interface is named in an `[ImplementInterface]` on the class: add the member to the interface **and delete it from the class**. The existing "add to interface" action stays |
| **Remove redundant property** | IMPLINTF008 | delete the property. Supports fix-all (document, project, solution) |
| **Delete member** | IMPLINTF009 | delete the mismatched hand-written member |

- IMPLINTF008 is a new `DiagnosticAnalyzer` beside `InterfaceImplementationAnalyzer`. It shares the
  redundancy rule with the INTF001 action through one helper.
- **INTF001 needs no other change.** It reads `namedTypeSymbol.Interfaces` after generators have run,
  so it already sees interfaces added by `[ImplementInterface]`. Its
  `ConfigureGeneratedCodeAnalysis(None)` keeps it out of our generated file. A test pins this down.
- The CS0535 fix depends on spike S6.

## Spikes

Each spike is a throwaway compile in the scratchpad. It takes minutes, its result gets written back
here, and it does not ship.

| Spike | Question | Decides |
|---|---|---|

Does a struct auto-property initializer with no constructor hit CS8983 on the consumer's LangVersion? Which constraints must an abstract method repeat (implicit implementation of a generic interface method)? Does `#nullable disable annotations` around oblivious members produce any warning? | R3 |
| **S2 — "Already implemented" detection** | Does `FindImplementationForInterfaceMember` see members written by hand in other partial parts, base-class members, and explicit implementations? Are members from other generators' output invisible, as expected? | R2.3 and R9 |

| **S4 — Error UX** | With an unsupported member, is "emit anyway, plus IMPLINTF003" better than "skip the base list"? Compare the error lists from the IDE and `dotnet build` | R5 |
| **S5 — Accessibility** | Public target, internal interface, internal property type: CS0053 vs CS0050. Does the explicit fallback compile? | R3 |
| **S6 — Code fix for a compiler id** | Does a `CodeFixProvider` with `CS0535` in `FixableDiagnosticIds`, shipped from `analyzers/`, get offered in VS and Rider? | R7 |

### Spike outcomes (2026-10-26)

- **S1** (compiled in a scratch project):
  - `set` cannot implement `init` (CS8854).
  - `= default!` is fine with primary constructors on classes, records and record structs.
  - A struct with an instance auto-property initializer and no constructor is CS8983, so structs get no instance
    initializer. Structs raise no CS8618, so nothing is lost.
  - An abstract implementation of a generic interface method must repeat its constraints (CS0425), so they are
    emitted.
  - Abstract events, indexers, get-only, set-only and ref-returning properties compile.
  - An explicit implementation cannot be abstract (CS0106/CS0071), so `Explicit = true` on an abstract class reports
    IMPLINTF003/004 for non-read/write members.
  - `#nullable disable annotations` raises no warnings.
- **S2** (reasoned, then covered by tests): `FindImplementationForInterfaceMember` returns null for an interface that
  is not yet in the base list, and the attribute's interfaces are not, until the generator adds them. So the generator
  does its own lookup: the type and its base types are searched for a public member with the same name, signature and
  type, and hand-written explicit implementations count too. A same-named member that does not match is IMPLINTF009.
  Members from other generators' output stay invisible, as documented.
- **S3**: `ForAttribute` fires once per attributed partial part, and separately for each attribute form. Only the call
  that owns the type's first attribute (in `GetAttributes()` order) builds the model and reports diagnostics; the
  others return nothing. The merge therefore happens in `Discover`, and the cached model is one per type.
- **S4**: emit anyway. The base list and every supported member are generated beside the IMPLINTF003/004/005 error,
  so code that uses the interfaces keeps compiling, and the build still fails on the one real error.
- **S5**: a public class implementing an internal property type publicly is CS0053, and the explicit implementation
  compiles. The fallback is implemented and tested.
- **S6**: the provider is registered for CS0535 and tested by invoking it directly against a compiler diagnostic. It
  has not been checked by hand in VS and Rider.

### Implementation notes

- The pipeline model holds pre-rendered member declarations (strings) and the base list, not a member tree. Every
  decision (collision fallback, initializer, abstract shape) is made in `Discover`, so the cached value is plain text
  and compares cheaply.
- IMPLINTF009's message names the mismatch: "'{member}' does not implement '{interface member}': it is {what}. Fix
  it, or delete '{member}' and let [ImplementInterface] implement it."
- A hand-written property that implements the first interface's same-named property forces the explicit fallback for
  the second interface, instead of reporting IMPLINTF009.

## Migration / Backward Compatibility

This is purely additive: two new attributes, a new generator, a new analyzer, new rule ids, and one
extra INTF001 code action. Existing code is untouched. Suppose a class already implements the
interfaces by hand and then gains the attribute. It generates nothing, because every member is
skipped, and IMPLINTF008 offers to delete the hand-written properties that are now redundant.

## Acceptance Criteria

- The CarDealer example from the overview compiles with an empty class body, and
  `CarDealerContext` is assignable to both interfaces.
- A method on either interface is IMPLINTF003 on a concrete target, unless it is written by hand,
  in which case the build is clean. On an abstract target it becomes `public abstract`.
- A get-only interface property is IMPLINTF004 on a concrete target unless it is written by hand.
- Every IMPLINTF rule and every R7 code fix has a test. The guard and caching coverage tests pass.
- Generated output is a single, fixed `ImplementInterface.g.cs` regardless of the number of targets.
- README and CHANGELOG are updated, and the rules are listed in `AnalyzerReleases.Unshipped.md`.
